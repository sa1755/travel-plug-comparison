# Production readiness quality audit

Audit date: 18 August 2026

## Product and safety

- Comparison URLs lead with the named route and one prominent outcome.
- A material voltage difference is never hidden behind plug-adapter guidance.
- When both actions apply, the primary answer explicitly says to bring an
  adapter and check the device voltage.
- Eight common-device cards distinguish Works, Adapter needed, Check label, and
  Do not connect yet. Exact labels and manufacturer instructions remain final.
- Same-country comparisons are rejected by schemas, server routes, and the live
  selection journey.

## Rendering and performance

- The production build generated 274 route outputs. The public-launch sitemap contains 265 URLs:
  homepage, device checker, 242 country pages, 15 plug pages, and four featured
  comparisons.
- Country, plug, and featured comparison routes are statically generated.
  Other valid comparisons render on demand and remain shareable.
- The globe, WebGL renderer, Natural Earth geometry, and city data load only
  after a visitor opens Explore. The primary comparison does not depend on it.
- Globe canvas dimensions follow its actual responsive container through
  `ResizeObserver`; reduced-motion users receive no automatic rotation.
- No content raster images or unoptimized image elements are used. Plug diagrams
  are inline SVG and metadata artwork is generated by Next.js.

## Accessibility and interaction

- A visible-on-focus skip link precedes the sticky header.
- Searchable country comboboxes expose labels, listbox state, keyboard movement,
  clear actions, no-results recovery, and full country names with flags/codes.
- Native radio controls remain available for device selection, now with visual
  device icons and clear selected states.
- Device results move focus to the new answer; dialogs close with Escape and
  return focus to the Explore trigger.
- Focus rings are visible, touch targets are at least 44px, and status meaning
  pairs colour with text and an icon.
- Safe, warning, and danger surfaces use the documented semantic tokens. Motion
  and smooth scrolling collapse under `prefers-reduced-motion`.

## SEO and trust

- Every public route has canonical metadata, a unique title/description where
  applicable, Open Graph/Twitter artwork, sitemap and robots coverage.
- The root includes WebSite JSON-LD structured data.
- The footer states the electrical review date, safety caveat, and a visible
  source link. Detailed sources and modelling decisions remain in
  `src/data/README.md`.

## Automated evidence

- ESLint uses the Next.js Core Web Vitals rules.
- TypeScript runs in strict no-emit mode.
- Sixty unit and component tests cover schemas, catalog integrity, domain
  branches, search, forms, device guidance, answer hierarchy, and invalid live
  journey state, analytics consent, affiliate filtering, and privacy preferences.
- HTTP smoke tests cover representative pages, metadata/discovery assets, the
  265-URL sitemap, generated imagery, and invalid-route recovery.
- Six real-browser journeys pass in desktop Chromium and a Pixel 7 viewport,
  covering comparison/swap, search, globe/list access, reduced motion, device
  guidance, repository links, and source links.
- The optimized Next.js Webpack build completes with 274 route outputs.
- GitHub Actions runs lint, strict type checking, unit/component tests, the
  production build, HTTP smoke tests, and the browser suite for pushes and pull
  requests targeting `main`.

The local gate is `npm run lint`, `npm run typecheck`, `npm test`,
`npm run build`, `npm run test:e2e`, and `npm run test:browser`. Live deployment
verification remains a separate release operation and must not be inferred from
a local build.
